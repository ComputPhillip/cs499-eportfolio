Artifact and Purpose

I selected the Python checkers project associated with my IT 450 coursework for my CS 499 ePortfolio. My earlier solution proposal was dated August 16, 2026. For this enhancement, the selected source baseline is Checkers_v24.py, supplied on November 1, 2026; its exact original creation date is not established. This version provides a two-dimensional board, standard and custom setups, human and computer play, and text-file saving and loading. Its computer opponent filters moves using rules and randomly chooses among the remaining options. The minimax and knowledge-base features discussed in the earlier proposal are not present in this baseline.

The artifact supports my focus on computer graphics because rendering, interaction, and visible game state are central to its use. The software design enhancement reorganizes the application so that graphics and rules can evolve independently. It also adds animated movement and legal-destination highlights. All seven supplied files were preserved in an original folder, and their copied contents were verified against the supplied files using SHA-256 hashes. The enhanced application is stored separately.

Design Changes and Portfolio Value

The original Tile class combines piece information with graphical objects, and constructing a tile immediately draws it. That design makes a game-state change dependent on a window. The enhanced model.py defines pieces, moves, legal actions, and turn transitions without importing the interface. view.py owns the canvas objects and coordinate conversion, while app.py coordinates user input and animation. Separate ai.py and storage.py modules contain opponent selection and persistence. These boundaries make responsibilities easier to identify and allow rules to be tested without opening a window.

The enhanced renderer scales the board with the window, marks legal destinations, and animates movement through timed callbacks. It reuses existing piece objects and deletes objects that are no longer needed. The controller invalidates pending animation or computer callbacks when the game is reset. This work demonstrates modular design, event-driven programming, resource management, and the connection between a reliable model and an understandable graphical interface.

Correctness and Validation

A concrete defect in the original capture routine helped establish the need for stronger separation and testing. The routine uses division to calculate list indexes. Under Python 3, those expressions produce floating-point values, and an isolated capture check reproduced a TypeError. The enhanced model represents board positions with integer coordinate pairs and explicitly removes the captured piece. Its legal-move interface also restricts a continuing capture to the same piece and handles positions where the current player has no legal action.

The enhanced application explicitly ends a turn when a pawn is crowned. This is a documented behavior change from the original implementation, which could continue capturing after promotion. The computer opponent also has a revised one-move heuristic that evaluates successor positions and uses random tie-breaking. These changes mean the enhancement is more than a structural refactor. Neither improved playing strength nor identical opponent behavior is claimed, and minimax remains part of the later algorithms milestone.

All 10 automated tests passed during initial validation on November 1, 2026. They cover standard move generation, mandatory and chained captures, rejection of an illegal move without mutation, promotion, backward king movement, blocked players, legal computer decisions, preservation of a capture continuation during saving and loading, legacy import, and selected invalid records. A separate hidden-window Tkinter smoke check verified coordinate round trips, animation completion, and reset during animation. Repeating the standard-board render 100 times held the canvas at 112 objects. That result supports bounded object use in that scenario; it does not establish a frame-rate improvement or complete interface correctness.

Reflection on the Enhancement Process

The central design lesson is that visible behavior depends on state management. Animating a piece introduces a period when its displayed position is changing while the logical move is still pending. The controller therefore blocks competing board actions during animation and uses a generation token to prevent callbacks from an older game from changing a reset game. Separating these concerns makes the behavior easier to reason about and gives future features a clearer place in the architecture.

Another lesson is that preserving an original artifact does not require preserving every defect or undocumented rule. Changes to capture handling, promotion, and opponent ordering need to be explained and checked separately from changes to appearance. The architecture and tests make those differences reviewable. This version does not yet include a documented instructor or peer feedback cycle. The next review should address usability, rule expectations, and the clarity of the module boundaries, with resulting revisions recorded in the milestone narrative.

"""American checkers rules; no window, disk access, or global mutable state."""
from dataclasses import dataclass, field
from typing import Optional

Square = tuple[int, int]


@dataclass(frozen=True)
class Piece:
    color: str
    king: bool = False


@dataclass(frozen=True)
class Move:
    start: Square
    end: Square
    captured: Optional[Square] = None


@dataclass
class Game:
    board: dict[Square, Piece] = field(default_factory=dict)
    turn: str = 'White'
    forced: Optional[Square] = None
    winner: Optional[str] = None

    @classmethod
    def standard(cls):
        return cls({(x, y): Piece('White' if y < 3 else 'Black')
                    for x in range(8) for y in range(8)
                    if (x + y) % 2 == 0 and (y < 3 or y > 4)})

    @staticmethod
    def inside(square):
        return all(0 <= n < 8 for n in square)

    def candidates(self, square, captures_only=False):
        piece = self.board.get(square)
        if not piece or piece.color != self.turn:
            return []
        x, y = square
        directions = (-1, 1) if piece.king else ((1,) if piece.color == 'White' else (-1,))
        moves = []
        for dy in directions:
            for dx in (-1, 1):
                near, far = (x + dx, y + dy), (x + 2 * dx, y + 2 * dy)
                other = self.board.get(near)
                if other and other.color != piece.color and self.inside(far) and far not in self.board:
                    moves.append(Move(square, far, near))
                elif not captures_only and self.inside(near) and near not in self.board:
                    moves.append(Move(square, near))
        return moves

    def legal_moves(self):
        if self.winner:
            return []
        if self.forced is not None:
            return self.candidates(self.forced, captures_only=True)
        moves = [move for square in self.board for move in self.candidates(square)]
        captures = [move for move in moves if move.captured is not None]
        return captures or moves

    def apply(self, move):
        if move not in self.legal_moves():
            raise ValueError('That move is not legal.')
        piece = self.board.pop(move.start)
        if move.captured is not None:
            del self.board[move.captured]
        crowned = not piece.king and move.end[1] == (7 if piece.color == 'White' else 0)
        self.board[move.end] = Piece(piece.color, piece.king or crowned)
        # American checkers ends the turn on crowning, even if a king could jump back.
        if move.captured is not None and not crowned and self.candidates(move.end, True):
            self.forced = move.end
        else:
            self.forced = None
            self.turn = 'Black' if self.turn == 'White' else 'White'
            if not self.legal_moves():
                self.winner = piece.color

    def resolve_terminal(self):
        if not self.legal_moves():
            self.winner = 'Black' if self.turn == 'White' else 'White'

"""Canvas renderer: owns drawing objects and coordinate conversion."""
import tkinter as tk


class BoardView(tk.Canvas):
    def __init__(self, parent, on_square):
        super().__init__(parent, background='#16202b', highlightthickness=0, width=640, height=640)
        self.squares = [self.create_rectangle(0, 0, 0, 0, outline='') for _ in range(64)]
        self.pieces = {}
        self.overlays = []
        self.snapshot = None
        self.selected = None
        self.moves = []
        self.bind('<Button-1>', lambda event: on_square(self.square_at(event.x, event.y)))
        self.bind('<Configure>', self.resize)

    def geometry(self):
        side = max(8, min(self.winfo_width(), self.winfo_height()) - 32)
        return (self.winfo_width() - side) / 2, (self.winfo_height() - side) / 2, side / 8

    def center(self, square):
        left, top, size = self.geometry()
        x, y = square
        return left + (x + .5) * size, top + (7 - y + .5) * size

    def square_at(self, px, py):
        left, top, size = self.geometry()
        x, row = int((px-left)//size), int((py-top)//size)
        return (x, 7-row) if 0 <= x < 8 and 0 <= row < 8 else None

    def resize(self, event=None):
        left, top, size = self.geometry()
        for y in range(8):
            for x in range(8):
                item = self.squares[y*8+x]
                px, py = left+x*size, top+(7-y)*size
                self.coords(item, px, py, px+size, py+size)
                self.itemconfigure(item, fill='#374c58' if (x+y)%2 == 0 else '#d9e1df')
        if self.snapshot is not None:
            self.render(self.snapshot, self.selected, self.moves)

    def position_piece(self, square, center):
        oval, label = self.pieces[square]
        x, y = center
        radius = self.geometry()[2] * .36
        self.coords(oval, x-radius, y-radius, x+radius, y+radius)
        self.coords(label, x, y)

    def render(self, game, selected=None, moves=()):
        self.snapshot, self.selected, self.moves = game, selected, list(moves)
        for square in list(self.pieces):
            if square not in game.board:
                for item in self.pieces.pop(square):
                    self.delete(item)
        for square, piece in game.board.items():
            if square not in self.pieces:
                self.pieces[square] = (self.create_oval(0,0,0,0,width=3), self.create_text(0,0))
            oval, label = self.pieces[square]
            self.position_piece(square, self.center(square))
            self.itemconfigure(oval, fill='#f4f2e9' if piece.color=='White' else '#17232b',
                               outline='#f5bd4f' if square==selected else '#91a5ad')
            self.itemconfigure(label, text='K' if piece.king else '',
                               fill='#17232b' if piece.color=='White' else '#f4f2e9',
                               font=('Segoe UI', max(10,int(self.geometry()[2]*.26)), 'bold'))
            self.tag_raise(oval)
            self.tag_raise(label)
        for item in self.overlays:
            self.delete(item)
        self.overlays = []
        for move in moves:
            x,y = self.center(move.end)
            radius = self.geometry()[2]*.12
            self.overlays.append(self.create_oval(x-radius,y-radius,x+radius,y+radius,fill='#f5bd4f',outline=''))
